# 暗黙的前提知識変化検出システム (Unspoken Context Change Detection System)

講義の書き起こしテキストにおいて、話者が明示的な説明なしに新しい前提知識を暗黙的に導入する**暗黙的前提知識変化（Unspoken Context Change: UCC）**ポイントを検出する実験的システムです。

## 暗黙的前提知識変化（UCC）とは？

**暗黙的前提知識変化（UCC）**は、専門家である話者がトピックの連続性を保ちながらも、**事前に明示的に確立されていない新しい前提知識を要求し始める**現象です。この現象は特に教育コンテンツにおいて問題となります：

- 話者が学習者に不足している可能性のある前提知識を仮定する
- 新しい概念や用語が定義なしに導入される
- 前提知識の変化が明示的ではなく暗黙的である
- トピックの連続性が概念的ギャップを隠してしまう

**例：**
> "セマンティックな関係性を測るためにコサイン類似度を使います。正規化されたベクトルの内積が類似度スコアになります。"

話者は「コサイン類似度」から「内積」や「正規化されたベクトル」にジャンプしていますが、これらの前提知識を説明せずに使用しており、暗黙的前提知識変化が発生しています。

## システム概要

本システムは、字幕テキストにおけるUCCポイントを識別するための**2つの相補的な検出アプローチ**を提供します：

### 1. 埋め込みベース検出（高速・低コスト）

**セマンティック埋め込み**を使用してContext Debt分析により前提知識の変化を検出します。

**主な特徴：**
- バッチ埋め込みによる高速処理
- 低コスト（埋め込みAPIのみ）
- 非対称ウィンドウによるスライディングウィンドウ分析
- Context Debt指標：過去コンテキストと現在コンテキストの意味的ギャップを測定
- 欠落している前提知識の自動キーワード抽出

**最適な用途：**
- 大規模な書き起こし分析
- 迅速なプロトタイピングと実験
- コストに敏感なアプリケーション
- リアルタイムまたは準リアルタイム処理

**詳細なアルゴリズム仕様は`SPEC.md`を参照してください。**

### 2. LLM直接検出（高精度・推論ベース）

構造化されたプロンプトによる**直接的なLLM推論**を使用して前提知識の変化を識別します。

**主な特徴：**
- 明示的な推論による高精度検出
- 各検出された変化に対する重大度スコアリング（1-5）
- 学習者向けマイクロサジェスション（≤120文字）
- チャンク間でのローリング前提知識メモリ
- 欠落概念の明示的識別
- 再現性のための決定論的キャッシング

**最適な用途：**
- 高リスクな教育コンテンツ
- 説明的介入の生成
- 評価のためのオラクル/ベースライン
- 研究と詳細な分析

**詳細な仕様は`SPEC2.md`を参照してください。**

## 比較：埋め込みベース vs LLM直接検出

| 側面 | 埋め込みベース | LLM直接検出 |
|------|--------------|-----------|
| **速度** | 高速（バッチ埋め込み） | 中程度（逐次的なLLM呼び出し） |
| **コスト** | 低い（埋め込みのみ） | 高い（チャットAPI呼び出し） |
| **精度** | 良好（統計的検出） | 優秀（明示的推論） |
| **説明可能性** | キーワード抽出 | 明示的な前提知識 + サジェスション |
| **重大度スコアリング** | 連続値（0-1） | 離散値（1-5）+ 根拠 |
| **キャッシュサポート** | 埋め込みをキャッシュ | レスポンス全体をキャッシュ |
| **最適なユースケース** | 大規模分析 | 高精度介入 |

## クイックスタート

### 前提条件

1. Python 3.8以上
2. OpenAI APIキー

### インストール

```bash
# 依存関係のインストール
pip install -r backend/requirements.txt

# 環境設定
cp .env.example .env
# .envを編集してOPENAI_API_KEYを追加
```

**注意:** スクリプトがPATHにないという警告が表示される場合は、`~/.local/bin`をPATHに追加してください：
```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

### システムの起動

#### 埋め込みベース検出（ポート8000）

```bash
# 起動スクリプトを使用
./start_embedding.sh

# または手動で
uvicorn backend.main:app --reload --port 8000
```

ブラウザで http://localhost:8000 を開いて、インタラクティブビューアにアクセスしてください。

#### LLM直接検出（ポート8001）

```bash
# 起動スクリプトを使用
./start_llm.sh

# または手動で
uvicorn backend_llm.main:app --reload --port 8001
```

ブラウザで http://localhost:8001 を開いて、インタラクティブビューアにアクセスしてください。

## 使用例

### Webインターフェース

両モードともインタラクティブなHTMLビューアを提供し、以下が可能です：
1. 字幕ファイル（.vttまたは.srt）のアップロード
2. 検出パラメータの設定
3. スコア付きでマークされたセグメントの表示
4. 閾値によるフィルタリング
5. 詳細なスコアと理由の検査

### API使用例

#### 埋め込みベースAPI

```bash
curl -X POST "http://localhost:8000/api/analyze" \
  -F "file=@subtitles.vtt" \
  -F "video_id=XXXX" \
  -F "language=ja" \
  -F "k_minus=12" \
  -F "k_plus=3" \
  -F "lambda_param=1.5"
```

**パラメータ：**
- `k_minus`: 過去ウィンドウサイズ（デフォルト：12）
- `k_plus`: 現在ウィンドウサイズ（デフォルト：3）
- `lambda_param`: 閾値の乗数（デフォルト：1.5）
- `tau_topic`: トピック連続性閾値（デフォルト：0.55）

#### LLM直接API

```bash
curl -X POST "http://localhost:8001/api/analyze" \
  -F "file=@subtitles.vtt" \
  -F "video_id=XXXX" \
  -F "language=ja" \
  -F "chunk_size=15" \
  -F "overlap=3" \
  -F "model=gpt-4o-mini"
```

**パラメータ：**
- `chunk_size`: チャンクあたりのセグメント数（デフォルト：15）
- `overlap`: チャンク間のオーバーラップ（デフォルト：3）
- `model`: LLMモデル名（デフォルト：gpt-4o-mini）

### コマンドラインインターフェース

```bash
python cli.py analyze \
  --input path/to/subtitles.vtt \
  --video-id XXXX \
  --language ja \
  --output-dir results/
```

## アーキテクチャ詳細

### 埋め込みベースモードのアーキテクチャ

```
入力（VTT/SRT） → パーサー → 前処理 → 埋め込み
                                      ↓
結果JSON ← キーワード理由 ← UCC検出器 ← コンテキストウィンドウ
          ↓
     HTMLビューア
```

**コアアルゴリズム：**
1. 字幕セグメントのパースと前処理
2. 全セグメントの埋め込み計算（キャッシング付き）
3. スライディングウィンドウ：コンテキスト埋め込み計算（平均プーリング）
4. Context Debt計算：`D(t) = ||c_plus(t) - c_minus(t)||`
5. スパイク検出：`ΔD(t) > μ + λσ`
6. セグメントのマーキングとキーワード理由抽出

### LLM直接モードのアーキテクチャ

```
入力（VTT/SRT） → パーサー → 前処理 → チャンカー
                                      ↓
                   ローリング前提知識 ← LLM（キャッシュ）
                                      ↓
結果JSON ← マークマージャー ← チャンク結果（マーク + 更新）
          ↓
     HTMLビューア
```

**コアアルゴリズム：**
1. 字幕セグメントのパースと前処理
2. オーバーラップチャンクの作成（サイズ15、オーバーラップ3）
3. 各チャンクに対して：
   - セグメント + 確立された前提知識でプロンプト構築
   - 決定論的設定でLLM呼び出し（temp=0.0）
   - マーク抽出（id、重大度、前提知識、サジェスション）
   - ローリング前提知識の更新
4. オーバーラップチャンク間でマークをマージ
5. マークスパンに基づいてセグメントにスコアを割り当て

## 設定

### 環境変数

`.env`ファイルを作成：

```bash
# 必須
OPENAI_API_KEY=sk-...

# オプション - 埋め込みモード
EMBEDDING_MODEL=text-embedding-3-large
EMBEDDING_CACHE_DIR=.cache/embeddings

# オプション - LLMモード
LLM_MODEL=gpt-4o-mini
LLM_TEMPERATURE=0.0
LLM_CACHE_DIR=.cache/llm_chunks
```

## 出力フォーマット

両モードとも互換性のあるJSON出力を生成します：

```json
{
  "video_id": "xxxx",
  "language": "ja",
  "params": { ... },
  "segments": [
    {
      "id": 42,
      "start_ms": 45100,
      "end_ms": 48600,
      "text": "コサイン類似度は内積を使います。",
      "is_marked": true,
      "reasons": ["内積", "ベクトルのノルム", "正規化"],
      "scores": {
        "ucc_score": 0.88,
        "context_debt_delta": 0.61
      }
    }
  ]
}
```

LLMモードはさらに以下を含みます：
- `severity`: 1-5のスコアリング
- `micro_suggestion`: 学習者向けの短いヒント

## 制限事項

### 埋め込みベースモード
- 微妙な概念的変化を見逃す可能性
- キーワード抽出にノイズが含まれる場合がある
- 手動での閾値調整が必要

### LLM直接モード
- 長い書き起こしの場合、APIコストが高い
- 処理時間が書き起こしの長さに比例
- 品質がLLMモデルの能力に依存
